# Payment Calendar — 6 SKU смесителей

Автономный HTML-календарь для планирования оплат поставщику, товарных приходов и необходимого темпа продаж.

## Основная логика

- Счёт создаёт базовый график: 30% в дату счёта, 30% через 50 дней, 40% через 2 календарных месяца.
- По умолчанию на текущую дату финальных 40% количество из счёта пополняет остаток. Дату прихода можно изменить отдельно.
- Даты и суммы этапов можно менять вручную прямо в реестре счетов и платёжном календаре. Ручная дата фиксирует только выбранный этап; остальные даты остаются привязаны к своим базовым правилам. Сумма фиксированного этапа уменьшает остаток задолженности, а более поздние автоматические этапы пересчитываются.
- Даты этапов сохраняют порядок 30% → 30% → 40%. Пока дата прихода не изменена вручную, она следует за датой 40%. После ручной фиксации приход живёт независимо; кнопка ↺ снова связывает его с 40%. Любое изменение даты сразу пересчитывает нужный момент продаж, физическую доступность товара, кассовый разрыв и денежный поток.
- Можно добавлять отдельные платежи. Если привязать платёж к счёту, он уменьшит остаток по счёту и пересчитает последующие автоматические этапы. Платёж без счёта влияет только на денежный поток и необходимый план продаж.
- Продажи считаются недельными периодами, а деньги от продаж приходят через один календарный месяц после конца периода (значение можно изменить в настройках).
- План продаж ограничен доступным количеством товара; недостающая сумма отображается как внешнее финансирование.

## Запуск

Откройте `index.html` в браузере. Все данные сохраняются локально в `localStorage` этого браузера. Для переноса данных предусмотрены экспорт и импорт JSON.

`payment_calendar_6sku_v3.html` сохраняется как совместимый файл для старой ссылки и содержит ту же актуальную версию приложения.
